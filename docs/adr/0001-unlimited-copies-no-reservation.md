# Товар — файл-шаблон, продаётся неограниченно

Магазин продаёт шаблоны документов (PSD/PDF): один и тот же файл покупают сколько угодно раз.
Уникальности единицы товара нет, значит нет и дефицита.

Отсюда следует, чего в схеме **не будет**:

- нет `StockItem` — файл лежит полем на `Product`, а не отдельной строкой на каждую копию;
- нет `Allocation` — некого закреплять за покупателем, значит нет ни состояний
  `RESERVED/DELIVERED/RELEASED`, ни частичного уникального индекса «один файл — один покупатель»;
- нет резервирования на чекауте и нет его истечения — команда `expire_transactions` и её крон
  уходят целиком;
- нет «оплачено, но товара нет»: ответ 409 на callback Plisio становится невозможным состоянием;
- нет производного счётчика остатка (`available`) и прогноза «на сколько хватит стока» в статистике.

Ссылка на скачивание переезжает с `Allocation` на `OrderItem`: токен, срок его жизни и счётчик
скачиваний — поля строки заказа. Один купленный товар в заказе = одна строка = одна ссылка.

## Consequences

- `OrderItem.quantity` теряет смысл: купить два одинаковых файла нельзя. Количество фиксируется
  единицей, а на `(order, product)` вешается `UniqueConstraint`. На фронте счётчик количества в
  карточке и в корзине исчезает — корзина становится множеством товаров.
- `Product` нельзя удалять, пока по нему есть оплаченная строка заказа: файл нужен покупателю
  и через год, а страница покупок восстанавливается письмом в любой момент. Поэтому
  `OrderItem.product` стоит на `PROTECT`, а «убрать с витрины» — это `Product.is_active=False`,
  не удаление.
- Замена файла в карточке товара меняет то, что скачают **старые** покупатели: версионирования
  файла нет. Это осознанно — шаблон правится в одну сторону, «выдать ровно тот файл, что купили»
  потребовало бы снимка файла на строке заказа. Если понадобится, снимок добавляется полем
  `OrderItem.file` без изменения остальной схемы.
- Чекаут перестаёт быть дорогим для магазина (ничего не блокируется), но остаётся дорогим для
  Plisio и почты — защита от абьюза меняет обоснование, см. [ADR-0005](./0005-checkout-rate-limits.md).
- Инварианты, которые остаются в схеме: `Transaction.txn_id` уникален (повтор callback не плодит
  инвойсы), `(order, product)` уникальна, `OrderItem.token` уникален.
