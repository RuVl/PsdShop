# Динамический рендеринг: SPA людям, Django-HTML ботам, один URL

Опыт M2a показал, что «Django-шаблоны + Vue-острова» ([ADR-0009](./0009-server-rendered-storefront.md))
на практике обрастают обвязкой: manifest-хранилище статики с подпаткой под Chart.js,
переключение хранилищ по `sys.argv`, vanilla-скрипты там, где хотелось Vue. Заказчик выбрал
другой компромисс: интерфейс целиком на Vue, а требование индексации (Яндекс JS рендерит
нестабильно, а русская выдача - обязательна) закрывается **динамическим рендерингом**.

## Решение

Все HTML-запросы приходят в Django. Одна вьюха, один queryset, один мета-контекст - и две
подачи по `User-Agent` (`storefront/bots.py`):

- **Бот** (поисковики + превью-краулеры мессенджеров) получает полный серверный HTML:
  шаблоны `storefront/` - каталог, карточка товара.
- **Человек** получает **shell**: собранный vite `index.html`, в `<head>` которого Django
  подставляет мету этой страницы (`{{ storefront_meta }}` - title, description, canonical,
  hreflang, og, ld+json). SPA монтируется и дальше живёт сама, данные берёт из
  `/api/catalog/...`.

URL-пространство одно на всех (`backend/backend/urlspace.py`), vue-router его зеркалит,
язык - префикс пути в обеих подачах. Мета строится **одной функцией на маршрут**
(`storefront/seo.py`) и рендерится в обе ветки - это страховка эквивалентности контента.

## Почему это не клоакинг

Google прямо говорит, что dynamic rendering - не клоакинг, пока контент эквивалентен; URL
совпадают, данные обеих подач - одни и те же querysets, мета - общая. Санкции грозят за
*разный* контент, поэтому правило проекта: бот-шаблон рендерит те же данные, что отдаёт API,
и никогда - больше или меньше.

## Известные риски

- **Google считает подход legacy** (рекомендует SSR/SSG). Принимаем осознанно: решение
  диктует Яндекс, а полный SSR (Nuxt) по-прежнему означает второй рантайм и вторую систему
  переводов (аргументы ADR-0009 в этой части в силе).
- **Двойная вёрстка каталога** (Django-шаблон + Vue-компоненты). Цена подхода; бот-страницам
  не нужна пиксель-точность - при правках дизайна в них обновляется контент, не вид.
- **Список бот-UA надо поддерживать** (`BOT_UA_RE`). Забытый краулер получит shell - то же,
  что видит человек, деградация мягкая.

## Consequences

- vue-router и vue-i18n остаются; `?lang=` умирает - язык только в пути.
- Каталожный API возвращается: `GET /api/catalog/{countries,document-types,products[,<id>]}`,
  оба языка в каждом ответе (`name_en`/`name_ru`), страница - 24 карточки в обеих подачах.
- Vite снова собирает SPA целиком: хешированные ассеты в
  `backend/storefront/static/storefront/spa/`, `index.html` с Django-хуками переезжает в
  шаблоны как `shell.html` (`make spa`). `ManifestStaticFilesStorage` не нужен - хеширует vite.
- SPA-образ собирается в backend-Dockerfile (multi-stage, context - корень репозитория);
  nginx отдаёт только `/static/` и `/media/`, весь HTML проксируется на gunicorn.
- Нет сборки (`shell.html` отсутствует) - каталожные вьюхи отдают человеку бот-страницу с
  предупреждением в лог: сайт деградирует, но живёт.
- Сервисные страницы (`cart`, `purchases`, `unsubscribe`) существуют только в SPA: Django
  отдаёт на их URL shell с `noindex` всем, включая ботов.
