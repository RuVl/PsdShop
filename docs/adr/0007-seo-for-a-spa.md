# SEO для SPA: мета отдаёт Django, карточки не пререндерятся

> Заменено [ADR-0010](./0010-dynamic-rendering.md): идея «Django подставляет мету в
> index.html» вошла туда как shell-ветка, а отдача ботам серверного HTML по User-Agent -
> которую этот документ отвергал как клоакинг - принята с условием эквивалентного контента.

Фронт остаётся Vue 3 SPA. Но витрина на 80 стран живёт поиском, а SPA отдаёт краулеру пустой
`<div id="app">`: заголовок, описание и Open Graph карточки товара в HTML не попадают.

Классический ответ — пререндер на сборке (`vite build` + headless-браузер по списку роутов).
Для статики это работает, для каталога — нет: товары добавляются в админке, а пререндер знает
только то, что было в базе на момент сборки. Каждый новый товар требовал бы пересборки фронта.

Предлагается вместо этого:

1. `index.html` из сборки отдаёт **Django-шаблон**, а не nginx: nginx проксирует на бэкенд не
   только `/api/` и `/admin/`, но и HTML-роуты витрины (`/`, `/product/<slug>`, статические
   страницы). Вью подставляет в `<head>` `title`, `description`, `og:*`, канонический URL и
   `<script type="application/ld+json">` с `schema.org/Product` — из базы, на каждый запрос.
   Сама SPA монтируется как обычно, ассеты и все остальные пути остаются на nginx.
2. `django.contrib.sitemaps` отдаёт `/sitemap.xml` по активным товарам и странам, `/robots.txt`
   ссылается на него.
3. Пререндер на сборке — только для страниц, которые не зависят от базы (правила, контакты), и
   то по остаточному принципу.

Альтернативы, которые отвергнуты: SSR всего фронта (Nuxt/vite-ssr) — переписывание всего клиента
ради `<head>`; отдача краулеру отдельной версии по User-Agent — клоакинг, риск санкций.

## Consequences

- Django оказывается на пути HTML-запросов витрины. Вью тривиальная (один запрос за товаром,
  шаблон из `dist/index.html`), но `collectstatic`/сборка фронта должны класть `index.html` туда,
  где его видит Django — либо шаблон читается из общего volume, либо копируется на деплое.
- Ошибка в этой вью роняет витрину целиком, поэтому она обязана падать мягко: нет товара — отдаём
  тот же `index.html` без специфичной меты и позволяем SPA показать свою 404.
- Роутинг определён дважды: список HTML-путей есть и в `router/index.js`, и в `urls.py`. Держать
  их рядом в одном месте документации обязательно.
- Решение помечено `proposed`: если SEO не приоритет, дешевле оставить чистую SPA и не тащить
  Django в HTML-путь вовсе.
